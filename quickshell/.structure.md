# Estructura ideal del proyecto
quickshell/
├── config/                        # CAPA 1: Estilos, Colores y Constantes
├── services/                      # CAPA 2: Lógica de Negocio e IPC (Sin UI)
├── components/                    # CAPA 3: Primitivas Visuales Atómicas y Reutilizables
└── modules/                       # CAPA 4: Ensambles y Ventanas Finales (Shell)

## Syntax conventions
- Cada clase definirá id, anchors, margins, others, propertys en ese orden, estableciendo los atributos others en orden alfabetico, ejemplo:
```qml
PanelWindow {
    id: root
    anchors { top: true; left: true; bottom: true}
    margins { left: 5; top: 5; bottom: 5; right: 5 }
    color: "transparent"
    implicitWidth: 32; implicitHeight: 32
    property int size: 32
}
```
- Se usará una notacion in line para establecer valores a los atributos de anchors, margins y implicitHeight/Width, ejemplo: 
anchors { top: true; left: true; bottom: true }
margins { left: 5; top: 5; bottom: 5; right: 5 }
implicitWidth: 32; implicitHeight: 32
- Los imports se definirán al inicio siendo los primeros los correspondientes a las librerías "Quickshell*", "QtQuick*", seguido de imports del proyecto.
- Los nombres de las variables deberán ser en ingles y usando **Style conventions**

## Style conventions

- All QML files: `import QtQuick`
- Properties: camelCase (e.g., `errorMsg`, `currentIndex`)
- Components: PascalCase filenames (e.g., `PopupButton.qml`, `IconButton.qml`)
- Services: PascalCase matching export name (e.g., `Audio.qml`, `Network.qml`)
- Use `??` for defaults, `?.` for optional chaining
- Use `Loader` with `asynchronous: true` for lazy loading
- Avoid `sh -c` with template literals for shell commands — use positional args

## Shell command safety

DANGEROUS — DO NOT use:
```qml
proc.exec(["sh", "-c", `echo '${userData}' > /path`])  // injection if userData contains '
```

SAFE pattern:
```qml
proc.exec(["sh", "-c", "printf '%s' \"$1\" > \"$2\"", "sh", userData, path])
```
